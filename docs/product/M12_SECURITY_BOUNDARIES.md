# M12 — Security Boundaries

## Process execution risks

M12 executes FFmpeg as an external process using `runCommand` (argument array, `shell: false`). Key constraints:

### Path validation (CRITICAL)

1. **Video path**: Resolved from `project.videoPath` stored in DB. Must:
   - `path.resolve()` to absolute
   - `stat().isFile()` check before passing to FFmpeg
   - Never contain user-supplied path fragments in the IPC payload

2. **Output path**: Constructed server-side only:
   ```typescript
   const resolvedOutputDir = path.resolve(project.outputDirectory);
   const outputPath = path.join(resolvedOutputDir, `${job.id}.mp4`);
   ```
   - `job.id` is a UUID generated by main process — safe as filename component
   - `project.outputDirectory` from DB — resolved before use
   - Validate `resolvedOutputDir` does not contain `..` after resolve

3. **Temp SRT path**: `path.join(os.tmpdir(), `${job.id}.srt`)`
   - `job.id` UUID — safe as filename
   - `os.tmpdir()` is platform-safe

4. **FFmpeg binary path**: Resolved by `checkFfmpegAvailability` — never renderer-controlled. IPC payload carries `candidateId` only; binary path is resolved server-side from DB settings.

### No shell interpolation

All FFmpeg arguments are in a `string[]` array. Filter graph string is built programmatically:
- `gblur=sigma=20` — static
- `subtitles={tmpPath}` — temp SRT path only; colon escaped for subtitles filter syntax
- `force_style='...'` — all style values come from enum-validated DB columns
- Font color `#RRGGBB` → `&H00BBGGRR` — pure hex transformation, no user input injection possible

### SRT content sanitization

Subtitle text from `clip_cues.text` column. Before writing to temp SRT:
- Strip `<` and `>` HTML tags (already stripped by subtitle parser, but re-strip as defense-in-depth)
- SRT format uses sequence numbers and timestamps — both generated, not from user input
- The subtitle cue text field is bounded at parse time (M2: 500 char/cue cap)

### Resource limits

- `timeoutMs`: computed server-side, capped at `300_000` ms — renderer cannot override
- `maxOutputBytes`: `10_485_760` — renderer cannot override
- No renderer-controlled exec parameters of any kind

### Output file open (shell.openPath)

`shell.openPath(path)` does NOT execute arbitrary code — it opens a path in the OS default handler. Still:
- Validate `outputPath` against known safe prefix (project's output directory)
- Resolve and check `isFile()` before calling
- Reject if path contains `..` after resolve

No new URIs, no new protocol handlers, no new `allowRunningInsecureContent`.

## Concurrent render safety

M12 enforces that at most one render job for a given `candidateId` can be in `status IN ('queued', 'rendering')` at any time. This is enforced at the **DB level** via a partial unique index (see `M12_DATABASE_STRATEGY.md`), not just application-level check. Application-level check-then-insert would be a TOCTOU race under rapid double-click.

Implementation: `createRenderJob(candidateId)` is wrapped in a try/catch for `SQLITE_CONSTRAINT` violations. If the partial unique index fires, `AppError('RENDER_ALREADY_IN_PROGRESS', ...)` is thrown and returned as a structured error.

## Fire-and-forget error guarantee

`render:startForCandidate` launches the render asynchronously (fire-and-forget). The async body MUST be wrapped with a top-level `try { ... } catch (err) { await db.updateRenderJobStatus(jobId, { status: 'failed', renderErrorCode: 'INTERNAL_ERROR' }); }` to ensure all failure paths produce a terminal DB status. An unhandled rejection would leave the job stuck at `queued`/`rendering`, permanently blocking re-render via the unique index.

## App-quit lifecycle

On app-quit (before-quit / will-quit Electron event), any in-progress render job is recorded as `INTERRUPTED_BY_RESTART` via the startup reconciliation logic (see M12_DATABASE_STRATEGY.md). The stored child process handle is killed on quit. Startup reconciliation on next launch clears any remaining stuck rows.

## Path containment algorithm

When validating that a path is within an expected base directory, use:
```typescript
const rel = path.relative(resolvedBase, resolvedTarget);
const isSafe = !path.isAbsolute(rel) && !rel.startsWith('..');
```
NOT `resolvedTarget.startsWith(resolvedBase)` — which is bypassed by sibling directories sharing a prefix (e.g., `/out` vs `/out-secret`).

## Symlink policy for videoPath and outputDirectory

Consistent with M1 (which uses `stat().isFile()` not `lstat().isFile()`), M12 accepts symlinked `videoPath` and `outputDirectory`. Symlinks are resolved by `path.resolve()` → `stat()` chain. No change from existing behavior.
